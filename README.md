# 🚀 Local Inference Performance Tester

A strict, deterministic benchmarking tool designed to evaluate local LLMs (via oMLX, vLLM, or LM Studio) on Apple Silicon. It bypasses SSD KV Caching to measure true Time-To-First-Token (TTFT) and real-world generation speed (TPS) during complex Python coding tasks.

## ⚙️ Features
* **100% Cache-Miss Guarantee:** Injects UUIDs to force cold-read prefilling.
* **True TPS Calculation:** Isolates TTFT from generation time for highly accurate token-per-second metrics.
* **Live Streaming:** Streams model outputs character-by-character to a secondary terminal window.
* **Script Archiving:** Saves every model's generated python code for post-mortem debugging.
* **Automated Matrix Reports:** Generates beautified Markdown tables comparing models across Easy, Medium, and Hard tasks.

## 🛠️ Setup

1. **Install the package locally:**
   ```bash
   pip3 install -e .
   ```
2. **Create the Configuration:**
   Create a `benchmark_config.json` in the root directory. Add your API endpoints, the models you have loaded/downloaded in oMLX, and your test prompts.

## 💻 Usage (The Dual-Terminal Setup)

For the ultimate developer experience, this tool splits the process logic and the token stream into two separate windows. 

**1. Open Terminal 1 (The Observer Window)**
Navigate to the project root and open the live stream pipeline:
```bash
touch live_stream.txt && tail -f live_stream.txt
```

**2. Open Terminal 2 (The Control Window)**
Navigate to the project root and trigger the benchmark:
```bash
tester
```

Terminal 2 will handle process management, script execution, and validation, while Terminal 1 will stream the AI's python code character-by-character as it is generated by your Mac's neural engine.

## 📊 Results Output
When the benchmark completes, a timestamped folder is created in the `results/` directory containing:
* `matrix_report.md`: A beautified Markdown table showing Pass/Fail and TPS speed for every model across every task.
* `benchmark_results.csv`: Raw data for external processing.
* `scripts/`: A folder containing the exact `.py` files generated by the models during the run.
